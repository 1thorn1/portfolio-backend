# CLAUDE.md

Spring Boot API for a portfolio site: visitor counter + guestbook. Java 17, Spring Boot 4.1, Gradle, PostgreSQL.

## Commands

```bash
./gradlew bootRun        # run locally (needs a Postgres reachable per config below)
./gradlew test           # run tests
./gradlew bootJar        # build build/libs/portfolio-backend-0.0.1-SNAPSHOT.jar
docker build -t pb .     # build the deploy image (multi-stage, same as Render)
```

## Architecture

- `com.juhee.portfolio_backend` — root; feature packages `comment/`, `visitor/`, plus `config/`.
- Each feature is a flat `Controller` / `Service` / `Repository` / entity set. No DTO layer beyond
  records nested in the controllers.
- **comment**: `GET/POST /api/comments`, `DELETE /api/comments/{id}` (requires header
  `X-Admin-Key` matching `admin.secret-key`).
- **visitor**: `GET /api/visitors/count` — logs one `visitor_log` row per `(client IP, date)` then
  returns the total row count. Client IP comes from `X-Forwarded-For` (first entry) else `remoteAddr`.
- **config/WebConfig**: CORS allow-list for `/api/**`. Keyed on the **frontend** origin (Vercel),
  not the backend host — no change needed when the backend URL changes.
- Schema is managed by Hibernate `ddl-auto=update` (no Flyway/Liquibase).

## Configuration

`src/main/resources/application.properties` is **gitignored**. The deployed jar has no bundled
properties file — every value comes from env vars / `-D` flags. See `application.properties.example`.

| var | meaning |
|---|---|
| `SPRING_DATASOURCE_URL` / `_USERNAME` / `_PASSWORD` | Postgres connection |
| `JPA_DDL_AUTO` | Hibernate schema mode (`update`) |
| `ADMIN_SECRET_KEY` | guestbook delete auth (bound via `@Value("${admin.secret-key}")`, so it
  must be passed as `-Dadmin.secret-key=...`, not the env var alone) |
| `PORT` | HTTP port |

Local dev: run Postgres (`docker run -d -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres
-e POSTGRES_DB=portfolio -p 5432:5432 postgres:17-alpine`), `cp application.properties.example
application.properties`, `export ADMIN_SECRET_KEY=dev`.

## Deployment — Render

Hosted on **Render** (migrated off Railway, 2026-09). Config is the `render.yaml` blueprint at the
repo root.

- **Web service** `portfolio-backend` — `runtime: docker` (Render blueprints don't support native
  Java), built from `Dockerfile`, started by `docker-entrypoint.sh`. `autoDeploy: true` → every
  push to `master` rebuilds and redeploys.
- **Database** `portfolio-db` — Render PostgreSQL (free, Singapore).
- **Live URL**: `https://portfolio-backend-p51a.onrender.com` (the bare `portfolio-backend`
  subdomain was taken globally, so Render appended `-p51a`).
- `docker-entrypoint.sh` converts Render's injected `DATABASE_URL` (`postgresql://user:pass@host/db`)
  into Spring's `SPRING_DATASOURCE_URL` (`jdbc:postgresql://...`) + username/password, and binds
  Spring to `$PORT` (default `10000` — the health check fails if the app comes up on 8080).
- `ADMIN_SECRET_KEY` is set by hand in the Render dashboard (`sync: false` in the blueprint);
  everything else is injected from `portfolio-db`.
- Health check path is `/api/comments`. Free instances sleep after 15 min idle (~30 s cold start).

### Frontend coupling

The frontend is a separate repo, `../portfolio-frontend` — a static `Portfolio.dc.html` on Vercel.
The backend URL is hardcoded there as `apiBase = '...'` (around line 217). If the Render URL ever
changes, update that line and push; Vercel auto-deploys.

## Gotchas

- Package is `com.juhee.portfolio_backend` (underscore) — `portfolio-backend` is not a valid
  Java identifier.
- A README-only commit still triggers a full Render rebuild because of `autoDeploy`.
- `GenerationType.IDENTITY` maps to Postgres `GENERATED BY DEFAULT AS IDENTITY`; if you ever bulk-
  insert rows with explicit ids, reset the sequence with `setval(pg_get_serial_sequence(...), max_id)`.
